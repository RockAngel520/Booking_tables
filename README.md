# Сайт для бронирования столиков в ресторане

Проект сайта для бронирования столиков в ресторане, разрабатываемый в рамках диплома.


## Технологии

- **Python** 3.13
- **Django** - веб-фреймворк
- **Bootstrap** - CSS-фреймворк для стилизации
- **PostgreSQL** - СУБД PostrgeSQL для хранения и обработки данных
- **Docker** и **Docker-Compose** - контейнеризация приложения


## Настройка переменного окружения

### Переименуйте файл .env.example в .env и заполните его следующими переменными:

**Общие настройки Django:**
- SECRET_KEY - секретный ключ безопасности Django-проекта
- DEBUG - включение режима отладки (True — включен, False — выключен)

**Подключение к PostgreSQL:**
- DATABASE_NAME - название базы данных
- DATABASE_USER - имя пользователя для подключения к БД
- DATABASE_PASSWORD - пароль пользователя базы данных
- DATABASE_HOST - адрес сервера базы данных (для запуска локально - 'localhost', для запуска через Docker - 'db')
- DATABASE_PORT - порт для подключения к БД

**Конфигурация почтового сервера:**
- EMAIL_HOST - SMTP сервер для отправки писем
- EMAIL_PORT - порт SMTP-сервера
- EMAIL_USE_TLS - использование шифрование TLS (True или False)
- EMAIL_USE_SSL - использование шифрование SSL (True или False)
- EMAIL_HOST_USER - электронная почта для авторизации на SMTP-сервере
- EMAIL_HOST_PASSWORD - пароль для доступа к почтовому аккаунту


## Установка и запуск

### Установка проекта

1. **Клонирование репозитория**
   ```
   git clone https://github.com/RockAngel520/Booking_tables.git
   cd Booking_tables
   ```
   
2. **Установка зависимостей через pip**
   ```
    pip install -r requirements.txt
   ```

3. **Применение миграций**
    ```
    python manage.py migrate
    ```

4. **Создание суперпользователя**
   ```
    python manage.py createsuperuser
   ```
   
5. **Запуск сервера разработки**
    ```
    python manage.py runserver
    ```
   
6. **Открытие в браузере**
    ```
    http://127.0.0.1:8000/
    ```
   

## Функциональность
### Публичные маршруты:
- Главная страница (/) — домашняя страница ресторана
- О ресторане (/about/) — информация о ресторане
- Столики (/tables/) — просмотр доступных столов

### Маршруты для авторизованных пользователей:
- Бронирование (/booking_create/) — создание новой брони
- Мои бронирования (/bookings/) — список всех бронирований пользователя
- Детали бронирования (/booking/<id>/) — подробная информация о конкретной брони
- Редактирование брони (/booking_update/<id>/) — изменение существующей брони
- Отмена брони (/booking_confirm_delete/<id>/) — удаление бронирования

### Авторизация и управление аккаунтом:
- Регистрация (/users/register/) — создание нового аккаунта
- Вход (/users/login/) — авторизация пользователя
- Выход (/users/logout/) — завершение сеанса

### Административная панель:
- Админка (/admin/) — управление данными через Django Admin


## Шаблоны (основные):
- home.html — главная страница
- about.html — страница "О ресторане"
- tables.html — список всех столиков
- bookings.html — список бронирований пользователей (требуется авторизация пользователя)

- booking_update.html — форма редактирования брони (требуется авторизация пользователя)

- booking_confirm_delete.html — подтверждение удаления брони (требуется авторизация пользователя)
- login.html — форма входа
- register.html — форма регистрации


## Функциональность

### Система бронирования столиков
- **Проверка доступности в реальном времени** — проверка свободных столиков на выбранные дату и время
- **Интерактивный выбор времени** — выбор времени через плиточный интерфейс с возможностью ограничений
- **Валидация бронирования** — проверка доступности столика на выбранные дату и время
- **Ограничения по времени** — нельзя забронировать стол раньше текущего времени + 10 минут
- **Ограничения по дате** — бронирование возможно только на 60 дней вперед
- **Кастомный виджет времени** — отображение времени в виде плитки с удобным выбором

### Управление бронированиями
- **Создание брони** — онлайн-бронирование с выбором столика, даты, времени и количества гостей
- **Просмотр броней** — список всех бронирований пользователя с сортировкой по дате
- **Детальная информация** — просмотр полных деталей конкретного бронирования
- **Редактирование брони** — изменение параметров существующей брони (дата, время, столик, гости)
- **Отмена бронирования** — удаление брони с подтверждением и отправкой уведомления
- **Разделение доступа** — пользователи видят только свои брони, персонал — все бронирования

### Пользовательская система
- **Аутентификация по email** — кастомная модель пользователя с email как основным идентификатором
- **Регистрация** — создание аккаунта с отправкой приветственного письма на email
- **Дополнительные поля** — имя, фамилия, телефонный номер в профиле пользователя
- **Разделение ролей** — обычные пользователи и сотрудники с разными правами доступа

### Уведомления по email
- **Подтверждение бронирования** — автоматическая отправка письма при создании новой брони
- **Уведомление об изменениях** — оповещение при редактировании существующей брони
- **Подтверждение отмены** — уведомление об успешной отмене бронирования
- **Приветственное письмо** — отправка email после успешной регистрации
- **Обработка ошибок отправки** — логирование проблем с отправкой email без прерывания работы

### Управление столиками
- **Каталог столиков** — просмотр всех доступных столиков с фотографиями и описаниями
- **Вместимость столиков** — каждый столик имеет максимальное количество гостей
- **Отключение столиков** — возможность временно убрать столик из бронирования

### Валидация и безопасность
- **Проверка прав доступа** — пользователи могут редактировать/удалять только свои брони
- **Персонализированный доступ** — сотрудники имеют доступ ко всем бронированиям
- **Защита от CSRF-атак** — использование csrf_exempt только для API-эндпоинтов
- **Валидация формы** — проверка корректности введенных данных на стороне сервера

### Навигация и интерфейс
- **Главная страница** — приветственная страница ресторана
- **Страница "О нас"** — информация о ресторане и его особенностях
- **Адаптивные формы** — стилизованные формы с использованием Bootstrap
- **Система сообщений** — отображение статусных сообщений об успешных операциях


## Для запуска через Docker:
В настройках переменных DATABASE_HOST должно быть указано 'db'.
Для запуска использовать команду:
    ```
    docker-compose up --build
    ```

### Основные команды при использовании Docker:
    ```
    # Остановить контейнеры
    docker-compose down

    # Запустить снова (без пересборки)
    docker-compose up

    # Перезапустить с пересборкой
    docker-compose up --build

    # Запустить в фоновом режиме
    docker-compose up -d

    # Проверить статус контейнеров
    docker-compose ps
    ```
